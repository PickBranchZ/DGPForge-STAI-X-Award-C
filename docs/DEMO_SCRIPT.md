# DGPForge Optional Future Walkthrough Script

This outline is optional recording prep material only. It is not required for the current public
mirror submission, and the repository is complete without a recorded walkthrough.

## 0:00-0:20 Problem

"Synthetic-data tools usually ask whether generated rows look realistic. DGPForge asks a different question: can we generate a simulation study where the statistical truth is known, then benchmark methods against that truth?"

## 0:20-0:50 Run DGPForge

Show:

```bash
python scripts/build_demo.py
```

Explain that this rebuilds the static demo gallery, all scenario reports, and the mini benchmark results. The YAML contracts define covariates, treatment assignment, outcome model, estimand, sample sizes, replications, seed, and estimators.

## 0:50-1:25 Show Report And Known Truth

Open `examples/generated_reports/index.html`, then the observed-confounding report. Point to the true ATE card, sample sizes, replications, and known-truth workflow. Emphasize that the simulator creates potential outcomes `Y0` and `Y1`, so the target estimand is known.

## 1:25-1:55 Show Estimator Evidence

Use the estimator table and plots. In observed confounding, the naive estimator is biased, while adjusted OLS and AIPW move closer to truth under this simple linear DGP. Point to `MCSE bias` and `MCSE coverage`: these are Monte Carlo precision diagnostics from finite replications, not single-dataset estimator standard errors.

## 1:55-2:15 Show Public-Health Count/Rate Feature

Open `examples/generated_reports/count_rate_outcome/report.html`. Point to the exposure-offset explanation, true rates under treatment and control, rate difference, rate ratio, and exposure diagnostics. Say: "This is the public-health use case: counts per denominator, but the benchmark target is still known by construction."

## 2:15-2:30 Show Missingness Or Clustering Validity Check

Open either `examples/generated_reports/missing_data/report.html` or `examples/generated_reports/clustered_icc/report.html`.

For missingness, point to the configured MAR mechanism, observed missingness rate, complete-case sample size, and full-data truth caveat.

For clustering, point to the target/empirical ICC and the naive vs cluster-robust SE comparison. Say: "Point estimates may look similar, but uncertainty and coverage change when the DGP is clustered."

## 2:30-2:40 Show Binary Outcome Feature

Open `examples/generated_reports/binary_outcome/report.html`. Point to `E[Y(1)]`, `E[Y(0)]`, risk difference, risk ratio, and marginal odds ratio. Say: "The logistic treatment coefficient is conditional. DGPForge benchmarks estimators against the marginal causal target on the probability scale."

## 2:40-2:48 Show Calibration As Design-Agent Capability

Open `examples/generated_reports/calibration_demo/calibration_report.html`. Point to requested vs achieved treatment prevalence and baseline outcome prevalence. Say: "The user can think in design targets; the tool converts those targets into DGP parameters and then checks the achieved synthetic design."

## 2:48-2:54 Show Sensitivity Grid

Open `examples/generated_reports/unmeasured_confounding_sensitivity/report.html`. Point to the heatmap and explain that latent `U` is generated by the DGP but hidden from observed estimators. Emphasize that this is a controlled synthetic stress test, not proof that hidden confounding is absent in real data.

## 2:54-2:57 Show Expansion Pack 1 Briefly

Open the double-robustness report. Explain that AIPW variants deliberately misspecify the propensity model, outcome model, or both. The point is conditional: in this seeded synthetic DGP with positivity, one-correct nuisance variants should be closer to known truth than the double-misspecified variant.

Open the scenario-grid report. Point to the compact grid summary and plots across sample size, confounding strength, and heterogeneous-effect coefficient. Emphasize that this is an illustrative grid, not an exhaustive benchmark suite.

## 2:57-3:05 Show From-Text Parser

Run:

```bash
dgpforge from-text --input examples/paper_excerpt_causal_ate.txt --out examples/generated_reports/from_text_demo
```

Open the assumptions log. Note that the parser is curated, records missing details, and does not claim general paper reproduction.

## 3:05-3:25 Show Optional LLM-Assisted Mode

Run:

```bash
dgpforge draft --prompt "Create a simulation with binary treatment, continuous outcome, moderate confounding, 500 units, 100 replications, and compare naive, IPW, and AIPW." --provider mock --out examples/generated_reports/llm_draft_demo --run
```

Open `draft_dgp.yaml`, `assumptions_log.md`, `validation_report.md`, and `report.html`. Say: "The mock LLM drafts the contract and logs assumptions. DGPForge validates the contract before execution, then deterministic modules generate the known truth, Monte Carlo evidence, diagnostics, and report."

Then show `examples/generated_reports/paper_llm_demo/extraction_trace.md` and `examples/generated_reports/config_review_demo/review_report.md` from the gallery. Note that paper-to-DGP mode is assisted extraction, not general paper reproduction, and review text is separated from deterministic checks.
